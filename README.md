令和8年度（2026年度）診療報酬改定対応：包括型訪問看護療養費 算定判定ロジック定義書

1. 本ドキュメントの目的と適用範囲

本ドキュメントは、令和8年度（2026年度）診療報酬改定にて新設される「包括型訪問看護療養費（区分番号０４）」をシステム上で自動判定・算定するためのテクニカルなロジック仕様を定義するものである。

本仕様は、エンジニアが医科点数マスタおよび日次スケジュールデータを基に、IF-THEN形式のプログラムコード（GAS, Python等）へ厳密に落とし込むための「正解ロジック」として機能する。実装に際しては、10円を1点とする「点数ベース」での計算を基本とし、医療保険（医科）における標準的なレセプト算出ロジックに準拠すること。

2. マスターデータ属性定義（算定前提条件のAssertion）

算定プロセスを開始する前に、以下のデータ属性がAssertion（表明）として満たされている必要がある。一つでも「False」がある場合、包括型（０４）の判定対象から除外され、出来高制の基本療養費（０１）等の判定へフォールバックする。

2.1 利用者属性マスタ

* Target_User_Flag (Boolean): 以下のいずれかがTrueであること
  * Is_Special_Disease：別に厚生労働大臣が定める疾病等（別表第7）に該当。
  * Needs_Special_Management：特別な管理を要する状態（別表第8）に該当。
  * Has_Special_Instruction：有効な「特別訪問看護指示書」が交付されている期間内。
* Has_Consent (Boolean): 包括型算定に対する利用者・家族の同意が電子的に記録されている。

2.2 施設・建物属性マスタ

* Is_Registered_Building (Boolean): 当該ステーションが包括型（０４）の届出を行った指定建物である。
* Has_24h_System (Boolean): 24時間対応体制加算の届出を行っている。
* Night_Staff_Gate (Boolean): 90分以上の高位区分を算定する場合、午後6時〜午前8時において、以下の配置基準を満たしているか。
  * Building_Resident_Count < 30 の場合：看護職員1名以上が常時待機/勤務。
  * Building_Resident_Count >= 30 の場合：利用者数に応じた増員（30:1比率基準）が満たされている。

2.3 運用・記録要件

* Is_Digital_Record (Boolean): 計画書および記録書が「電子的方法」により作成・保存されている。

3. 日次集計および論理ゲート（Daily Logic Gate）

1日（00:00〜23:59）のスケジュール実績データに対し、以下の4つのゲートを順次通過させる。

1. 訪問回数ゲート (Visit_Count_Gate):
  * Total_Visit_Count >= 2 であること。
2. 時間帯要件ゲート (Timeframe_Gate):
  * Daytime_Visit (08:00 <= T < 18:00) に少なくとも1回以上の訪問実績。
  * Nighttime_Visit (18:00 <= T < 08:00) に少なくとも1回以上の訪問実績。
3. 職種要件ゲート (Staff_Role_Gate):
  * 全訪問のうち、少なくとも1回以上 Staff_Type == 'RN'（保健師、助産師、看護師。准看護師は除外）による訪問が含まれていること。
4. 回数・時間整合性ゲート (Frequency_Duration_Consistency):
  * Aggregate_Daily_Time >= 60 (min) の場合、Total_Visit_Count >= 3 であること。

4. 算定区分判定マトリクス（点数ベース定義）

「単一建物居住利用者数」と「1日の合計訪問時間」に基づき、以下の点数を算定する。 ※10円を1点として換算。

単一建物居住利用者数	30分以上60分未満	60分以上90分未満	90分以上	90分以上かつ特定条件*
20人未満	701点	1,101点	1,401点	1,551点
20人以上50人未満	631点	991点	1,373点	1,520点
50人以上	596点	936点	1,345点	1,489点

*特定条件（Tier "Ni"）の判定ロジック

「90分以上かつ特定条件」を算定するためには、以下の数式を満たす必要がある。

* Building_Average_Time_Logic: SUM(当該建物内の全包括型利用者の1日合計訪問時間) / COUNT(当該建物内の全包括型利用者数) >= 120 (min) ※この計算は個人の実績ではなく、建物単位の集団平均時間で判定される点に注意せよ。

5. 排他制御および併算定ロジック

包括型（０４）を算定する日は、以下の排他制御コードを実装すること。

5.1 完全排他（同一日に算定不可）

* 訪問看護基本療養費（０１）
* 精神科訪問看護基本療養費（０１－２）
* 訪問看護管理療養費（０２） ※月の初日、2日目以降ともに不可

5.2 例外的に併算定可能な項目

* 加算項目:
  * 緊急訪問看護加算（注9）
  * 乳幼児加算（注11）
  * 24時間対応体制加算（区分番号０２の注2）
  * 基本療養費（Ⅰ）・（Ⅱ）の「ハ」（専門看護師等による共同訪問）
* 物価対応料:
  * 訪問看護物価対応料２（区分番号０８）：1日につき 2点（20円）を自動加算。

6. システム実装上の制約および境界値（Constraints）

エンジニアは、以下の例外処理およびデータ仕様を厳守すること。

* 合計時間の算出ロジック:
  * Assertion: 1回あたりの訪問時間に「20分」等の下限（Floor）は設定しない。数分単位の極めて短い訪問であっても、実提供時間であれば全て Aggregate_Daily_Time に加算する。
  * Boundary: Aggregate_Daily_Time < 30 (min) の場合は包括型（０４）の算定対象外（0点）とする。
* 単一建物居住利用者数の定義:
  * Constraint: 「同一月に当該ステーションから（０４）または（０２）を算定した当該建物内の延べ人数」とする。
  * Risk: 月の途中で入居者が増えた場合、月初に遡って「居住者数区分」が変動する可能性がある。日次の暫定計算時には「現時点の月内最大数」を参照する動的なロジックを推奨する。
* 他ステーションとの競合:
  * 当該建物に居住していても、包括型の届出を行っていない別ステーションが訪問した場合は、そのステーションは出来高制（０１）等で算定を行う。自システム内では「自ステーションが届出済みか」のフラグを最優先すること。
* エラーハンドリング:
  * 日中・夜間のセット訪問が1日の中で完結していないデータ（例：日中のみ）が包括型対象者に記録された場合、エラーログを吐き出し、算定不可として処理すること。
